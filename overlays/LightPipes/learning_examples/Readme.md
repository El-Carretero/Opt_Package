이 폴더는 **가우시안 빔의 자유공간 전파 → 두 슬릿의 회절·간섭** 순서로 진행하는 입문용 실습입니다. 설치된 LightPipes 2.1.5와 프로젝트 전용 `.venv`를 사용합니다. 추가 설치나 GPU는 필요하지 않습니다.

2. 마지막에 `Both examples passed`와 각 예제의 `ALL CHECKS PASSED`를 확인합니다.
3. 아래 그림을 순서대로 열어보세요. 같은 이름으로 다시 실행하면 해당 결과만 덮어씁니다. 연습 결과는 `--output-name`으로 별도 보관할 수 있습니다.

## 1. 가우시안 빔은 왜 퍼지는가?

코드: [01_gaussian_propagation.py](01_gaussian_propagation.py)

`Begin → GaussBeam → Forvard → Intensity`가 계산의 중심입니다. `GaussBeam`은 시작면의 빔을 만들고, **`Forvard`가 FFT와 프레넬 전파 전달함수로 실제 수치 전파**합니다. `GForvard`나 ABCD 해석적 가우시안 전파로 계산을 대체하지 않았습니다. 별도로 계산한 해석식과 FFT 결과를 비교합니다.

기본값은 파장 λ = **632.8 nm**, 빔 허리 반경 w₀ = **0.5 mm**, 계산창 한 변 **8 mm**, **512 × 512** 격자입니다. 시작면 z = 0이 빔 허리입니다.

```
I(r,z) = I(0,z) exp[-2 r²/w(z)²]
zR = π w₀² / λ
w(z) = w₀ √[1 + (z/zR)²]
```

여기서 **w는 세기가 그 면의 중심 세기의 1/e² ≈ 13.53%가 되는 반경**입니다. 지름은 2w입니다. 수치적으로는 `wₓ = 2σₓ`, `wᵧ = 2σᵧ`라는 세기의 2차 모멘트를 사용합니다. 가우시안 분포에서 이 값이 1/e² 반경과 같습니다. 임의의 비가우시안 빔에서는 둘을 같은 정의로 부를 수 없습니다.

| 위치 | 기본값의 예상 반경 | 의미 |
|---|---:|---|
| z = 0 | 0.500000 mm | 빔 허리 |
| z = zR ≈ 1.241148 m | 0.707107 mm | 허리 반경의 √2배 |
| z = 2zR ≈ 2.482295 m | 1.118034 mm | 허리 반경의 √5배 |

공간 분포 그림 세 장은 **모두 초기 중심 세기를 기준으로 같은 색 범위**를 씁니다. 따라서 넓어진 빔이 어두워집니다. 반면 중심 단면 그림은 각 면의 최고 세기로 따로 나누어 폭을 비교합니다. 입력 진폭은 임의 단위이므로 그림의 세기를 W/m² 또는 출력 파워 W로 해석하지 마세요.

### 바꿔볼 값

이 폴더에서 PowerShell을 열고 실행합니다. 아래 명령의 수치는 해당 옵션 이름의 단위입니다. 코드 내부와 CSV는 SI 단위(m)를 사용합니다.

```powershell
# 더 가는 초기 빔: zR이 줄어드는지 확인
& '..\.venv\Scripts\python.exe' '.\01_gaussian_propagation.py' --waist-mm 0.35 --output-name gaussian_small_waist

# 더 짧은 파장: zR이 늘어나는지 확인
& '..\.venv\Scripts\python.exe' '.\01_gaussian_propagation.py' --wavelength-nm 532 --output-name gaussian_green

# 같은 물리를 더 촘촘한 격자로 재계산
& '..\.venv\Scripts\python.exe' '.\01_gaussian_propagation.py' --grid 1024 --output-name gaussian_fine_grid
```

`--z-max-zr 2`는 끝 거리가 레일리 길이의 2배라는 뜻입니다. 파장이나 허리를 바꾸면 **실제 전파 거리(m)도 함께 바뀝니다.** 따라서 퍼짐 속도를 비교할 때는 JSON의 `rayleigh_range_m`과 CSV의 `z_m`을 보세요. 가로축 z/zR, 세로축 w/w₀로 정규화한 곡선은 같은 식으로 겹칩니다. 같은 실제 거리에서 작은 허리의 빔이 더 빠르게 발산한다는 관계와 모순되지 않습니다.

추가 옵션: `--window-mm`(계산창 한 변), `--grid`(한 변의 샘플 수), `--z-max-zr`(끝 거리), `--wavelength-nm`, `--waist-mm`. `--help`로 전체 옵션을 확인할 수 있습니다.

## 2. 이중 슬릿: 간섭과 회절 포락선

코드: [02_double_slit.py](02_double_slit.py)

`Begin → RectAperture × 2 → BeamMix → LensFarfield → Intensity`로 계산합니다. 두 슬릿을 **같은 위상·같은 진폭의 단색 평면파**로 비추고 이상적인 렌즈의 초점면을 관찰합니다. `LensFarfield`는 입력 복소장의 직접 FFT를 계산하고 초점면 좌표를 λf로 환산합니다. 이는 **이상적인 근축 렌즈의 초점면 / 프라운호퍼 회절** 예제이며, 임의 거리의 근접장 자유공간 전파 예제가 아닙니다.

기본값: λ = 632.8 nm, 슬릿 폭 a = **0.125 mm**, 중심 간격 d = **0.5 mm**, 높이 **1 mm**, 렌즈 초점거리 f = **500 mm**, 입력창 **8 mm**, **1024 × 1024** 격자입니다. 그림에서 흰색이 투과 슬릿입니다. y = 0의 가로 단면을 다음 해석식과 비교합니다.

```
I(x)/I(0) = sinc²[a x/(λ f)] × cos²[π d x/(λ f)]
sinc(u) = sin(πu)/(πu)
간섭의 cos² 주기 Δx = λ f / d = 0.6328 mm
단일 슬릿 포락선의 첫 영점 |x| = λ f / a = 2.5312 mm
```

좁은 간섭무늬는 두 슬릿의 **중심 간격 d**, 넓은 포락선은 각 슬릿의 **폭 a**가 정합니다. 포락선 때문에 전체 세기의 각 밝은 봉우리 위치는 순수 cos² 봉우리에서 조금 이동할 수 있습니다. 따라서 λf/d를 모든 봉우리 사이의 정확한 실측 간격으로 해석하지 마세요.

### 바꿔볼 값

```powershell
# 중심 간격을 절반으로: cos² 간섭 주기는 두 배, 포락선은 동일
& '..\.venv\Scripts\python.exe' '.\02_double_slit.py' --separation-mm 0.25 --output-name slit_half_separation

# 슬릿 폭을 두 배로: 포락선 폭은 절반, cos² 주기는 동일
& '..\.venv\Scripts\python.exe' '.\02_double_slit.py' --slit-width-mm 0.25 --output-name slit_wide

# 렌즈 초점거리를 절반으로: 초점면의 모든 가로 길이가 절반
& '..\.venv\Scripts\python.exe' '.\02_double_slit.py' --focal-length-mm 250 --output-name slit_short_focus
```

초점면의 샘플 간격은 `Δx_out = λf / L_in`입니다. 입력창이 고정이면 N을 늘려도 초점면의 샘플 간격은 그대로이고 관찰 범위가 넓어집니다. 이 예제의 입력창 L_in = 8 mm는 코드에 고정되어 있습니다. 슬릿 폭이나 간격을 임의의 값으로 바꾸면 픽셀로 표현한 유효 치수가 요청값과 약간 달라집니다. JSON에는 둘을 구분해 기록하고 해석식에는 **실제 샘플링된 치수**를 씁니다.

## 검증과 결과 파일 읽기

실행하면 각 `output/<이름>/`에 PNG, 수치 CSV, `results.json`, `validation.log`이 생성됩니다. 예를 들어 첫 실습의 검증 결과는 `output/01_gaussian/results.json`과 `output/01_gaussian/validation.log`입니다. CSV에는 단위가 열 이름에 적혀 있으며 Excel로도 열 수 있습니다. JSON은 입력값, 라이브러리 버전, 측정치, 각 판정 기준을 기록합니다.

| 점검 | Gaussian | 이중 슬릿 |
|---|---|---|
| 입력 샘플링 | 허리 반경당 20점 이상 | 슬릿 폭당 12점 이상 |
| 출력 샘플링 | 반경과 경계 에너지로 점검 | 간섭 주기당 12점 이상 |
| 해석식 일치 | 반경 상대 오차 < 0.1% | 첫 포락선 영점 안에서 정규화 세기의 최대 절대 오차 < 0.003 |
| 격자 수렴 | N→2N에서 끝면 반경 변화 < 0.1% | N→2N에서 중심 포락선 세기 변화 < 0.003 |
| 적분 세기 | 상대 변화 < 10⁻⁹ | FFT의 물리적 진폭 계수를 보정한 뒤 상대 변화 < 10⁻⁹ |
| 추가 점검 | 계산창 바깥쪽 10% 띠에 있는 세기 비율 < 10⁻⁵ | 요청한 폭·간격과 픽셀 치수 차이 < 2% |

기본값 실측: Gaussian 반경 최대 상대 오차 **9.73×10⁻¹¹**, 경계 세기 비율 **2.18×10⁻⁸**; 이중 슬릿 해석식 대비 최대 절대 오차 **0.001305**, 격자 증가에 따른 변화 **0.000979**. 둘 다 모든 검증을 통과했습니다. 이중 슬릿의 날카로운 경계는 픽셀로 이산화되어 연속 해석식과 작은 차이가 생깁니다.

이 배포에는 기본 예제의 대표 PNG만 포함합니다. 수치 CSV·JSON·검증 로그와 매개변수 연습의 결과는 사용자가 실행할 때 각 `output/` 하위 폴더에 생성됩니다. 아래 기준은 실행할 때 다시 평가합니다.

이 기준은 입문 예제에서 수치 결과를 믿을 수 있는지 확인하는 기준입니다. 파라미터를 바꾼 뒤 실패해도 PNG/CSV/JSON은 저장됩니다. 실패를 무시하기보다 원인을 확인하세요.

- Gaussian의 경계 검사 실패: FFT는 유한한 주기적 창을 사용하므로 가장자리에서 빔이 되돌아 들어올 수 있습니다. `--window-mm`와 `--grid`를 함께 늘리거나 전파 거리를 줄이세요. 총 세기 보존만으로 이 문제를 검출할 수는 없습니다.
- 샘플 수 부족: `--grid`를 늘리세요. Gaussian에서 계산창만 늘리면 픽셀 간격도 커져 작은 허리가 오히려 덜 분해됩니다.
- 이중 슬릿의 간섭 주기 샘플 수 부족: 입력창이 고정되어 있으므로 N 증가만으로 해결되지 않습니다. 중심 간격을 줄이거나, 코드를 공부한 다음 입력창 `window`를 늘리고 슬릿 폭 분해능도 함께 확보하세요.
- 이중 슬릿의 치수 또는 해석식 검사 실패: 더 촘촘한 격자를 쓰거나 픽셀 간격의 정수배에 가까운 슬릿 치수를 고르세요. 슬릿이 겹치지 않고 입력창 안에 충분히 들어오는지도 확인하세요.

## 이 실습의 범위

두 예제는 단색·스칼라·근축 파동광학입니다. 편광, 벡터 회절, 렌즈 수차, 실제 재료 분산, 유한 렌즈 구경의 추가 손실은 모델에 포함하지 않았습니다. 이중 슬릿의 표시 세기는 중심 최대값으로 정규화합니다. `LensFarfield` 자체의 FFT 출력은 물리적 진폭 정규화가 생략되어 있어, 적분 세기 검증에서만 `dx_in²/(λf)`를 곱합니다. 위상·절대 복사 측정값을 교정한 모델로 받아들이지 마세요.

검증 환경: **LightPipes 2.1.5 / Python 3.12.12 / NumPy 2.5.4 / Matplotlib 3.11.2**, Windows의 프로젝트 전용 `.venv`. 실행 당시의 정확한 버전은 각 `results.json`에도 저장됩니다. 기존 라이브러리 소스와 설치 메타데이터는 변경하지 않았습니다.

직접 구현을 읽으려면 상위 소스의 `LightPipes/propagators.py`에서 `Forvard`, `LightPipes/lenses.py`에서 `LensFarfield`, `LightPipes/core.py`에서 `RectAperture`를 찾아보세요. 공식 프로젝트는 [opticspy/lightpipes](https://github.com/opticspy/lightpipes)입니다.
